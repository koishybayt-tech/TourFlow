# Tourflow — CRM для турагентств Казахстана

Этот файл Claude Code читает в начале каждой сессии. Здесь — контекст продукта, правила и решения, которые нельзя нарушать.

## Что строим

B2B SaaS для турагентств Казахстана. Одна система закрывает:
- **заявки** от первого сообщения в WhatsApp/Instagram до вылета и возвращения;
- **авторские групповые туры** (конструктор тура, расчёт себестоимости, набор группы, публикация);
- **пакетные туры** туроператоров (поиск, подборка клиенту, бронь у оператора);
- документы (договоры из шаблонов, расписки, электронная подпись), оплаты, задачи, календарь, отчёты.

Пилотные клиенты: организатор групповых визовых туров (Ерлан), авторские туры Feel Free Travel, розничное агентство пакетных туров (по образцу Poedem). Цель среднего срока — переманить агентства с Битрикс24.

## Нерушимые правила продукта

- **Один менеджер ведёт клиента от начала до конца.** Заявка — одна страница с блоками сверху вниз, а не цепочка экранов.
- **Статус заявки меняется сам**, когда выполнены условия текущего статуса. Регламент этапа — подсказка «что осталось», а не блокировка. Ручная смена статуса разрешена и пишется в историю.
- **Системные задачи этапа** создаются при входе в этап и закрываются при выходе. Ручные задачи можно привязать к этапу; этап не завершится, пока они открыты.
- **Статус задачи меняется только кнопками** в карточке задачи: «Взять в работу» → «Завершить» (обязателен результат) → «Вернуть в работу».
- **Клиент — отдельная сущность**, ищется по нормализованному телефону (+7, 10 цифр). Дубли объединяются вручную.
- **Договор и расписки доступны в любой момент**, не привязаны к этапу. Отправка с незаполненными переменными разрешена после подтверждения.
- **Финансы тура скрыты от туристов.** Поступления от клиентов не смешиваются с прибылью.
- **Всё, что делает пользователь, пишется в историю** (кто, когда, что). Историю нельзя редактировать.
- **Деньги** — целые тенге (`Int`, без тиынов). Суммы в валюте — `Decimal(12,2)` + код валюты + курс и дата фиксации курса.

## Терминология (UI на русском)

- «Заявка» (не «сделка»). «Бронь у туроператора» (не «заявка у оператора»).
- «Выезд» — конкретная дата группового тура. «Тур» — авторский продукт с программой.
- «Расписка» — документ-подтверждение клиента (выбрал отель сам и т.п.).
- Валюта — ₸, формат `1 290 000 ₸` (пробел-разделитель тысяч).
- Даты — `14–21 ноября`, `22.10.2026`. Часовой пояс — Asia/Almaty.

## Стек (не менять без согласования)

Nuxt 4 + TypeScript (strict), Nuxt UI (Tailwind v4), Pinia, Prisma + PostgreSQL 16, Zod, nuxt-auth-utils (сессии), Motion for Vue (`motion-v`) для анимаций, ExcelJS для выгрузок, Vitest + Playwright, Docker Compose, GitHub Actions → GHCR. Подробности и версии — `docs/05_ARCHITECTURE.md`. Перед установкой пакета проверь актуальную стабильную версию (`npm view <pkg> version`).

## Как работать

- Работаем фазами по `prompts/NN_*.md`. Одна фаза — одна ветка `feat/NN-name` и один PR.
- В начале фазы: план в чате → дождись «ок» → реализация → `pnpm lint && pnpm typecheck && pnpm test` → краткий отчёт.
- Маленькие коммиты, Conventional Commits на английском (`feat(deals): auto-advance status`).
- Сначала тип и схема (Prisma + Zod), потом API, потом UI.
- Внешние интеграции (WhatsApp Cloud API, Instagram, Telegram, Tourvisor, NCALayer/eGov, Kaspi) — только через интерфейсы `server/providers/*` с mock-реализацией по умолчанию. Реальные ключи — только из `.env`, никогда в коде.
- Персональные данные (ИИН, паспорта) — шифрование на уровне поля, доступ журналируется, данные хранятся в Казахстане (закон РК о персональных данных).
- Не удаляй и не переписывай чужой рабочий код без причины. Не добавляй зависимости «на всякий случай».
- UI-тексты — только на русском, через i18n-ключи (`locales/ru.json`), чтобы потом добавить казахский.

pnpm lint && pnpm typecheck && pnpm test && pnpm test:e2e
