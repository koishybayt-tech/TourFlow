# 02. Функциональность и бизнес-правила

Эталон поведения — `reference/prototype.html`. Ниже — то, что должно работать в продакшене. «Демо» в прототипе = mock-провайдер здесь.

---

## 1. Оболочка приложения

- **Сайдбар** (сворачиваемый, на мобильном — выезжающий): Главная, Сообщения, Заявки, Задачи, Календарь, Клиенты · Групповые туры: Мои туры, Выезды, Гиды · Пакетные туры: Поиск туров, Брони у туроператоров · Отчёты, Авиабилеты и отели · Настройки. Пункты модулей скрыты, если модуль выключен. Бейджи: непрочитанные сообщения, просроченные задачи, выезды в риске.
- **Шапка:** глобальный поиск (клиенты, телефоны, заявки, выезды; ⌘K открывает палитру команд), колокольчик уведомлений, аватар + имя + логин, меню профиля (профиль, безопасность, уведомления, тариф, выход).
- **Вход:** email или телефон + пароль, «Запомнить устройство», «Забыли пароль?». Регистрация агентства (название, БИН, город, владелец). 2FA — позже.
- **Кнопки создания — на страницах**, не в шапке.

## 2. Главная — «Мой день»

- Четыре карточки фокуса (кликабельны): ждут ответа · задачи на сегодня (и просрочено) · оплаты на неделе · новые заявки.
- «Мои задачи на сегодня», «Ждут ответа», «Сегодня в календаре», «Оплаты и вылеты на неделе» (доплаты клиентов, оплаты туроператорам, вылеты в ближайшие 14 дней).
- Финансы и аналитика — только в «Отчётах».

## 3. Сообщения

- Единая лента WhatsApp + Instagram + форма сайта. Фильтры: Все · Новые · Без воронки · WhatsApp · Instagram.
- В строке диалога: аватар, имя, превью, время, канал, «Новое», «Есть заявка» или подсказка воронки «→ Пакетные туры».
- Окно диалога: шапка (имя, телефон, канал, «Создать заявку из диалога» / «Открыть заявку»), полоса рекомендации: «Рекомендация: Пакетные туры · по словам «турци», «всё включено» · 92% · Направление: Турция → Ерлан» + выпадающий список «Воронка заявки».
- Ответ клиенту: поле + шаблоны (подставляют текст) + «Отправить» (уходит в канал клиента, пишется в историю заявки) + ссылка «Открыть чат в WhatsApp ↗».
- Правая панель «Данные лида»: направление, даты, количество человек, виза, источник — переносятся в заявку.

### Определение воронки (порядок правил)
1. Метка из ссылки `[GT-p1]` в первом сообщении → воронка и выезд из настроек ссылок (100%).
2. Правило канала (WhatsApp/Instagram/Сайт → фиксированная воронка) (95%).
3. Ключевые слова по воронкам (начало слова: «анталь» найдёт «Анталью»). Уверенность = 55 + 15 × совпадений, максимум 92.
4. Иначе — очередь «Без воронки» или базовая воронка (настройка).
Позже правило 3 заменяется ИИ-классификатором с тем же интерфейсом.

### Создание заявки из диалога
- Клиент ищется по нормализованному телефону. Найден → заявка добавляется к его карточке (уведомление). Нет → создаётся клиент.
- Ответственный — по направлению (раздел 12). Создаётся системная задача первого этапа.

## 4. Заявки (список)

- Переключатель Канбан / Список, выбор воронки, фильтр по менеджеру, «Новая заявка».
- Канбан: колонка = этап, общий серый фон колонки вместе с заголовком, цветная полоса сверху (серая — первый этап, синяя — промежуточные, зелёная — финальный), счётчик и сумма. Карточка: клиент, тур, бейджи (источник, человек, даты), полоса оплаты «Оплачено N%» и сумма, ответственный и дата. Завершённые и отказные — не в канбане.
- Перетаскивание карточки между колонками = ручная смена статуса (с подтверждением, если регламент не выполнен; пишется в историю).
- «Новая заявка» — модалка: поиск клиента (имя/телефон) или «+ Новый клиент» (с проверкой дубля по телефону), воронка, запрос.

## 5. Страница заявки (главный экран)

Шапка: аватар, клиент, бейдж статуса, тур, человек, телефон, источник, направление · «Ведёт» (владелец меняет из списка; уведомление новому ответственному, открытые системные задачи переходят к нему) · «Сменить воронку» · «Отказ» (с обязательной причиной).

Над блоками — закреплённая навигация по шагам (номер или ✓, клик — раскрыть и прокрутить), «Свернуть готовые / Развернуть всё».

**Блоки** (пронумерованы; готовый блок свёрнут в одну строку с итогом, стрелка — раскрыть):

1. **Клиент и туристы.** Заказчик: «Данные N из 5» (ФИО полностью, ИИН, дата рождения, email, адрес) в две колонки, «Изменить», «Карточка клиента →». Туристы — таблица: №, ФИО как в паспорте, паспорт, действует до (красным, если < 6 мес. после поездки), виза; «+ Турист»; бейдж «2 из 3 внесено».
2. **Тур.** Групповой: выбор выезда (цена = цена выезда × человек), ссылка на выезд, количество, бюджет, визовая история. Пакетный: даты, количество, бюджет, «Найти туры», «Импорт варианта», карточки вариантов, бронь у туроператора, документы оператора (раздел 9). Базовый: запрос, даты, количество.
3. **Цена и оплаты.** Стоимость, оплачено, долг, срок полной оплаты, прогресс, список платежей, «Принять оплату» (сумма, тип, способ: Kaspi / наличные / карта / перевод), «Возврат / перенос» (раздел 5.3).
4. **Договор.** Статус (не сформирован / ждёт подписей / подписан), статусы подписей клиента и агентства, кнопка «Сформировать договор» — мастер (раздел 7).
5. **Расписки клиента.** Раздел 8.
6. **Виза** (только визовые туры). Запись в визовый центр (создаёт событие календаря), загрузка визы.
7. **Документы.** Все файлы заявки с типом, «Загрузить» (тип выбирается).
8. **Задачи.** Таблица задач заявки (раздел 10), «+ Задача».

**Правая колонка (закреплена):**
- Статус заявки: выпадающий список статусов, прогресс «N из M», «Статус меняется сам…», список «Осталось для следующего статуса» (клик — к нужному блоку), инлайн-действия типа «подтверждение»/«комментарий», «Завершить заявку» на последнем этапе.
- Переписка: последние 3 сообщения, «Открыть чат».
- Другие заявки клиента по телефону (в том числе успешные и отказы) со статусом и суммой.
- Заметки (внутренние, клиент не видит).
- История: последние 5 событий, «Показать всю историю».

### 5.1 Регламент этапов и автостатус
- У каждого этапа воронки: описание («что сделать») и список требований. Типы требований: ввод поля, документ (тип), подписание договора, оплата (предоплата от X ₸ на человека / 100%), комментарий, подтверждение (чекбокс), выбор выезда, туристы (все внесены), событие календаря (визовая запись), данные клиента для договора.
- Требование выполнено, если данные заявки ему соответствуют (вычисляется, не хранится флагом, кроме «подтверждения» и «комментария»).
- **Автопереход:** когда все обязательные требования текущего этапа выполнены и все ручные задачи этапа закрыты — заявка переходит на следующий этап (уведомление «Статус обновлён автоматически»). Делать на сервере в доменном сервисе после любой мутации заявки, идемпотентно.
- Регламент редактируется в «Настройки → Воронки и этапы → Регламент» (описание, требования: добавить/удалить/обязательно).

Регламенты по умолчанию — см. `docs/03_DATA_MODEL.md`, раздел «Сиды».

### 5.2 Отказ и смена воронки
- Отказ: причина из списка (Не устроила цена, Выбрал другое агентство, Не выходит на связь, Передумал, Отказ в визе, Другое) + комментарий.
- Смена воронки: целевая воронка, этап (предлагается этап с тем же названием или пропорциональный), выезд для групповой, причина. Системная задача старого этапа закрывается, создаётся для нового. Всё остальное сохраняется.

### 5.3 Возврат и перенос
Тип: возврат / перенос на другой выезд / замена туриста. Удержание по правилу агентства (настройка), сумма возврата, способ, комментарий. Возврат — отрицательный платёж.

## 6. Клиенты

- **Список:** одна строка на человека. Фильтры: Все · В работе · С поездками · С долгом · Дубли. Колонки: клиент (имя, телефон), статус («Новый», «Был в поездке», «Постоянный») и число заявок, последняя заявка и этап, менеджер, оплачено за всё время, источник, внимание (паспорт истекает, возможный дубль). Поиск: имя, телефон, ИИН. «+ Клиент».
- **Досье:** левая колонка (закреплена) — аватар, бейджи, быстрые действия WhatsApp/Позвонить/Email, контакты, ответственный, данные для договора с прогрессом, согласие на ПДн, первое и последнее обращение, метки-предпочтения (свои + подсказки), заметка, «Редактировать», «Объединить». Правая — 6 показателей (оплачено за всё время, поездок, в работе, средний чек, текущий долг, отказы), карточки активных заявок (этап с прогрессом, сумма/оплачено/долг, следующий шаг), вкладки: Все заявки · Хронология (все события всех заявок) · Туристы · Переписка · Оплаты · Документы.
- **Дубли:** похожие имя + первая буква фамилии при разных телефонах → «Возможный дубль». Объединение переносит заявки и данные, второй номер — как дополнительный. Необратимо, с подтверждением.
- Изменение данных клиента в карточке применяется ко всем его заявкам и будущим договорам.

## 7. Договоры и подписание

### 7.1 Шаблоны (Настройки → Шаблоны документов)
Мастер: 1) наименование, 2) воронка, 3) загрузка DOCX/PDF, 4) разбор — найденные переменные `{Любое_Имя}` показываются таблицей «переменная → поле заявки» с автоподбором по названию и примером значения; несвязанные подсвечены. Сохранение запрещено, пока есть несвязанные переменные. Предпросмотр на демо-заявке.

Поля для связки: клиент (ФИО, ИИН, дата рождения, адрес, телефон, email), поездка (тур, даты, количество, список туристов с паспортами, гид, отель, туроператор), оплата (стоимость, предоплата, оплачено, срок, правило возврата), договор (номер, дата, менеджер), компания (название, БИН, директор, адрес, банк, ИИК, БИК, лицензия, телефон).

Генерация документа — из исходного DOCX с подстановкой (docxtemplater), PDF — конвертация на сервере (LibreOffice в отдельном контейнере `gotenberg`).

### 7.2 Мастер «Документ на подпись» (в заявке)
Шаги с индикатором: **1 Шаблон** (поиск, «Для этой воронки / Все шаблоны», рекомендуемый выбран, у каждого «Не хватает данных: N») → **2 Предпросмотр** (лист A4, подсветка подстановок) → **3 Заполнение полей** (незаполненные — сразу инпутами; «Проверить заполнение переменных» показывает все; ручное значение помечается, «↺ Вернуть из заявки»; данные клиента сохраняются в карточку) → **4 Подписание** (сводка, предупреждение о пустых полях, «Отправить без N полей» → пустые места `______________`).
После отправки: номер договора, PDF в документах, две ссылки — клиенту и подписанту агентства (копировать, «Отправить в WhatsApp» с готовым текстом). Аннулировать и сформировать заново можно, пока никто не подписал.

### 7.3 Страница подписания (публичная, по токену)
Шапка (документ, статус, RU/KZ), просмотрщик (страницы, масштаб), панель справа: «Ожидает подписания», лента подписантов (Отправитель — агентство, Подписант — клиент; статус, раскрывающиеся детали), «Скачать документ ▾» (PDF / PDF с листом подписей / CMS), «Подписать документ» → выбор способа: **ЭЦП (NCALayer)** — окно NCALayer: тип хранилища, файл ключа, пароль; **eGov Mobile (QR)** — QR + 3 шага. Для агентства — выбор подписанта (директор или ответственный с правом подписи).
Провайдер подписи — интерфейс `SigningProvider` с mock; реальная интеграция — NCALayer (WebSocket на клиенте) и eGov Mobile (QR-сервис) — отдельная задача после MVP. Подписи хранить в CMS, проверять сертификат НУЦ РК.

## 8. Расписки клиента

- Шаблоны с условием показа: «Клиент сам выбрал отель» (выбран отель), «Сборы и депозит на месте» (выбран отель), «Условия аннуляции и штрафы», «Изменение курса валюты», «Отказ от страховки от невыезда», «Изменение времени чартерного рейса» (пакетный), «Риск отказа в визе» (визовый), «Срок действия паспорта» (все), «Выезд несовершеннолетнего» (есть дети). Тексты — в сидах (согласовать с юристом).
- В заявке: рекомендуемые отмечены, «Текст» (предпросмотр с данными), «На подпись» (та же механика ссылки), «Скан» (подписано на бумаге), «Отправить рекомендуемые · N» одной ссылкой. Счётчик «N из M подписано». Каждое действие — в историю.
- Настройки: список шаблонов с переключателями, свои — через загрузку шаблона.

## 9. Пакетные туры

### 9.1 Поиск туров
Фильтры: откуда (Алматы/Астана/Шымкент), страна, вылет с–по, ночей от–до, взрослые, дети с возрастом, цена до, питание, звёздность, туроператор. **Размещение по номерам** считается автоматически и показывается («1 номер: 3 взр. + 1 реб. (7 лет)»; до 3 взрослых и 4 человек в номере, дети — к взрослым). Результат — отели от минимальной цены, у отеля — предложения операторов (дата, ночей, цена за состав и за человека, комиссия), «В подборку» (если поиск открыт из заявки), «У оператора ↗».
Провайдер `TourSearchProvider`: mock + адаптер **Tourvisor API** (JWT из кабинета турагента; справочники, поиск, актуализация). Кэшировать справочники, поиск — асинхронно с поллингом.

### 9.2 Подборка и бронь (в заявке)
- Карточка варианта: оператор, отель и звёзды, курорт, даты и ночи, питание, номер, включено (перелёт/трансфер/страховка), нетто, комиссия, цена клиенту, цена за человека. Форма варианта с проверками (цена ≥ нетто, даты), «Наценка N%» по комиссии оператора. **Импорт варианта** из ссылки/текста/скриншота (парсинг текста + ИИ для скриншотов) → форма для проверки.
- «Отправить подборку (N)» — редактируемое сообщение в канал клиента.
- «Клиент выбрал» — остальные варианты «Не выбран», цена заявки = цена варианта.
- Порядок по рекомендации эксперта: туристы с паспортами → предоплата → бронь. «Открыть у оператора ↗» (deeplink из Tourvisor), «Создать бронь у оператора» (номер, дедлайн оплаты оператору — по условиям оператора, комментарий). Статусы брони: Запрос → Подтверждена (номер) → Оплачена (частичные оплаты оператору, долг) → / Аннулирована (причина, штраф).
- Документы оператора: ваучер, авиабилеты, страховой полис.
- Предупреждение, если клиент оплатил меньше, чем нужно отдать оператору к дедлайну.

### 9.3 Брони у туроператоров (реестр) и справочник
Показатели (активные брони, долг операторам, оплаты в 7 дней, комиссия), фильтры по статусу и оператору, таблица по срочности. Справочник операторов: название, условия оплаты, комиссия по умолчанию, контакт.

## 10. Задачи

- Статусы: Новая → В работе → Выполнена. Приоритеты: высокий/средний/низкий. Срок + время, исполнитель, автор, описание, подзадачи, привязка к заявке/выезду/этапу, история.
- **Смена статуса только кнопками** в карточке: «Взять в работу» → «Результат выполнения» (обязательно) + «Завершить задачу» → «Вернуть в работу».
- **Системные задачи этапа** (фиолетовый бейдж «Системная · этап X»): создаются при входе в этап; в карточке — плашка, описание этапа и интерактивные требования этапа; кнопка «Завершить задачу → этап «Y»». Нельзя удалить/переименовать.
- Ручная задача может быть привязана к этапу (по умолчанию при создании из заявки) — блокирует переход, её закрытие может перевести этап.
- Страница «Задачи»: быстрые вкладки (Все/Мои/Сегодня/Просроченные), поиск, фильтры (исполнитель, приоритет, связь), «Скрыть выполненные», Список (группы по сроку) и Канбан (3 колонки, без перетаскивания). Карточка — правая выезжающая панель.

## 11. Групповые туры

### 11.1 Мои туры (конструктор, по ТЗ Feel Free Travel)
Список: карточки с обложкой, флагами, маршрутом, датами, местами (продано/всего), ценой, прибылью при полной группе, безубыточностью. Фильтр по статусу: Черновик · Опубликован · Набор закрыт · Архив. «Создать тур», «Дублировать» (программа и описание сохраняются, цены перелётов/проживания/факт очищаются).

Редактор — вкладки:
- **Основное:** название, флаги, страны, маршрут, даты (дни/ночи считаются), мест, цена, предоплата, повышение цены после даты на сумму, условие оплаты остатка, описание, обложка (загрузка фото), автосохранение черновика.
- **Программа:** дни (номер, дата, город, достопримечательности-чипы, описание, переезды, фото/видео), перестановка, удаление, отметка «доступность в эти даты проверена».
- **Перелёты:** откуда, куда, дата, время, авиакомпания, билет, багаж, валюта, ссылка; итог на туриста и группу в ₸.
- **Проживание:** город, отель/апартаменты, заезд/выезд (ночи), номера, гости, стоимость за срок, валюта, ссылка, заметка о сезоне/событиях; итог на человека и группу.
- **Финансы** (скрыты от туристов): план/факт; прочие расходы (статья, план, факт, валюта или %, на туриста/на группу), быстрые статьи; курсы EUR/USD/CHF с датой фиксации; «Цены проверены» (предупреждение > 14 дней); показатели и сценарии (см. формулы ниже); экспорт в Excel.
- **Включено:** два списка «Включено» / «Дополнительно».
- **Публикация:** текст для Instagram (генерируется, редактируется, копируется), ссылки на посты/Reels, предпросмотр публичной страницы.

**Формулы (в KZT по курсам тура):**
```
variable = (Σ(перелёты: билет+багаж) + Σ(расходы на туриста)) × (1 + Σ%)
fixed    = (Σ(проживание за срок) + Σ(расходы на группу)) × (1 + Σ%)
cost(n)  = variable·n + fixed;  costPer = cost/n
revenue  = price·n;  profit = revenue − cost;  margin = profit/revenue
breakEven = ceil(fixed / (price − variable))  (если price > variable)
suggestPrice = round(costPer(seats) × 1.25, 10 000)  — только если все цены перелётов и проживания заполнены
```
Сценарии: 40%, 60%, 80%, 100% мест и точка безубыточности.

**Публикация** запрещена без: названия, дат, цены, программы, подтверждённой доступности всех дней. При публикации создаётся **выезд** (мест = мест тура, минимум = безубыточность, дедлайны: билеты −45 дн., полная оплата −30 дн., брифинг −7 дн.). Действия: Закрыть набор, Открыть набор, В архив, Удалить (с подтверждением).

### 11.2 Публичная страница тура (SSR, SEO)
`/t/[slug]`: обложка, название, маршрут, даты, продолжительность, цена, предоплата, свободные места, программа по дням, галерея, включено/дополнительно, кнопка «Забронировать в WhatsApp» (сообщение с названием и датами; ссылка с меткой → заявка в нужной воронке и выезде). Финансы не показываются. OG-теги для превью в мессенджерах.

### 11.3 Выезды
Плановая таблица по месяцам, карточка выезда: сетка мест (готовы/в процессе/свободно), участники (таблица: участник, шаг процесса — **вычисляется из этапа его заявки**, ответственный, оплачено, «Открыть заявку →» / «Создать заявку», «Возврат / перенос»), подсказка шага при наведении, автоматизация (при N готовых — задача «Купить авиабилеты», когда готовы все — «Забронировать гостиницу»), брони, день X, гид (подбор с проверкой занятости по датам и языка маршрута; «Лучший выбор / Подходит / С оговорками / Недоступен»). Отображение риска недобора.

### 11.4 Гиды
Карточки: ФИО, возраст, пол, языки, опыт (годы, агентства), ставка за выезд, рейтинг, отзывы, ближайшие выезды (снять с выезда), «Назначить на выезд». Плашка «N выездов без гида — Подобрать».

## 12. Распределение по направлениям

Настройки: направления (ключевые слова, ответственные, режим «Один»/«По очереди», резерв), доступность сотрудников (на работе / в отпуске), по умолчанию, «Проверить распределение». При создании заявки: направление по тексту → ответственный (round-robin среди доступных) → резерв, если все в отпуске. В заявке — бейдж направления.

## 13. Календарь

Месяц / Неделя / Список. Типы: встреча, звонок, визовая запись, вылет, оплата, задача, брифинг. Автособытия из выездов, задач, дедлайнов оплаты клиентов и туроператорам. Фильтры по типам и сотруднику. Создание события с проверкой конфликтов, привязкой к заявке/выезду и напоминанием (клиенту в WhatsApp, сотруднику в Telegram). Синхронизация с Google Calendar — позже.

## 14. Отчёты (только владелец)

Вкладки: Сводка (бары по источникам и менеджерам, воронка), Воронка и конверсия, Источники, Менеджеры (в т.ч. просроченные задачи), Выезды (заполненность, валовая), Долги (дебиторка и кредиторка), Отказы (причины). **Экспорт XLSX** (ExcelJS, форматирование, заголовок с компанией и периодом), «Скачать все», печать/PDF, еженедельная рассылка (email + Telegram, cron).
