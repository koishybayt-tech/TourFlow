# 01. Продукт

## Позиционирование

Tourflow — CRM для турагентств Казахстана с готовыми туристическими процессами. Главный аргумент против Битрикс24: настройка без разработчика и процессы, которые уже знают про визы, группы, туроператоров и расписки.

## Сегменты и их сценарии

| Сегмент | Пример | Главный сценарий |
|---|---|---|
| Организатор групповых авторских туров | Ерлан (визовые туры в Европу), Feel Free Travel | Собрать тур, посчитать себестоимость, набрать группу, провести каждого туриста от предоплаты до визы и вылета |
| Розничное агентство пакетных туров | По образцу Poedem | Подобрать тур у туроператоров, отправить подборку, забронировать, принять оплату, выдать документы |
| Среднее агентство с колл-центром | Агентства на Битрикс24 | Колл-центр принимает обращение, система распределяет по направлению, менеджер ведёт до конца |

## Роли

| Роль | Что видит и делает |
|---|---|
| **Владелец** | Всё: настройки, финансы, отчёты, все заявки, переназначение |
| **Менеджер** | Свои заявки, свои задачи, клиенты своих заявок. Без финансов агентства, отчётов и настроек |
| **Колл-центр** | Входящие сообщения, создание заявки, указание направления. Не видит оплаты и документы |
| **Гид** (позже) | Свои выезды, список участников, программа |

Права — на уровне API (проверка роли и владения записью), а не только скрытием кнопок.

## Модули (включаются в настройках организации)

| Модуль | По умолчанию | Состав |
|---|---|---|
| Ядро | всегда | Сообщения, заявки, клиенты, задачи, календарь, документы, оплаты, отчёты, настройки |
| Групповые туры | вкл. | Мои туры (конструктор), выезды, участники, гиды |
| Пакетные туры | выкл. | Поиск туров, подборки, брони у туроператоров, туроператоры |

| Команда и распределение | выкл. | Направления → ответственные, отпуска, очередь |
| Миграция с Битрикс24 | выкл. | Импорт лидов, сделок, контактов |

## Терминология

- **Заявка** — обращение клиента, которое ведёт менеджер. Имеет воронку и статус.
- **Воронка** — набор статусов: «Групповые туры», «Пакетные туры», «Базовая».
- **Статус (этап)** — шаг воронки. У этапа есть регламент (описание + обязательные действия).
- **Клиент** — заказчик (плательщик). **Турист** — участник поездки с паспортом; заказчик может быть туристом.
- **Тур** — авторский продукт (программа, расчёт, публикация). **Выезд** — конкретная группа на даты. Публикация тура создаёт выезд.
- **Вариант** — предложение туроператора в подборке клиента. **Бронь у туроператора** — подтверждённая заявка у оператора с номером и дедлайном оплаты.
- **Расписка** — подписанное клиентом подтверждение, защищающее агентство.
- **Направление** — география (Турция, ОАЭ, Европа-групповые…), к которой привязаны ответственные менеджеры.

## Ключевые пути пользователя

1. **Обращение → заявка.** Клиент пишет в WhatsApp/Instagram. Система предлагает воронку и направление, менеджер создаёт заявку одним кликом, ответственный назначается автоматически.
2. **Групповой визовый тур.** Данные клиента и туристов → выбор выезда → договор → предоплата → запись на визу → виза → полная оплата → готов к выезду. Статус меняется сам.
3. **Пакетный тур.** Поиск туров (размещение по номерам) → подборка в WhatsApp → клиент выбрал → туристы и паспорта → предоплата → бронь у оператора → оплата оператору → ваучер и билеты.
4. **Авторский тур.** Конструктор: программа по дням, перелёты, проживание, расходы, курсы → цена и безубыточность → проверка сезонной доступности → публикация на сайте и в Instagram → набор группы.

## Что вне MVP

Онлайн-оплата, личный кабинет туриста, мобильное приложение, маркетплейс, B2B между агентствами, ЭДО, реальная интеграция с GDS. Для всех — только интерфейсы-заглушки.
