# Решения по ходу разработки

Владелец проекта попросил вести разработку без остановок на утверждение планов. Вопросы фазы 0 решены разумными умолчаниями — они собраны здесь. Любое из них можно пересмотреть.

## Инфраструктура

| Решение | Почему |
|---|---|
| **SeaweedFS вместо MinIO** для S3 | С конца 2025 MinIO не публикует бесплатные Docker-образы (Docker Hub и quay.io отказывают в доступе). SeaweedFS — Apache 2.0, S3-совместим, код приложения не зависит от выбора. В проде — любой S3 в Казахстане. |
| **`NUXT_APP_SECRET`** вместо `NUXT_SESSION_PASSWORD` | Новая версия nuxt-auth-utils перешла на общий секрет Nuxt. |
| **Node 22 через `devEngines`** | Nuxt 4.6 не поддерживает Node 25. pnpm сам скачивает Node 22 для проекта, глобальная установка не трогается. |
| **TypeScript 5.9** | TS 7 (нативный компилятор) ещё не поддерживается vue-tsc. |
| **Prisma 7** с драйвером `@prisma/adapter-pg` | Актуальная стабильная версия; клиент генерируется в `server/generated/prisma`. |
| Локали в `i18n/locales/ru.json` | Стандартная папка @nuxtjs/i18n v10 (в документах был `locales/`). |
| PR через git без GitHub CLI | `gh` не установлен. Каждая фаза — ветка `feat/NN-*`, она сливается в `main` через merge-коммит и пушится; CI проверяет push в `main`. |

## Продукт (ответы на вопросы фазы 0 по умолчанию)

| Вопрос | Решение |
|---|---|
| Год туров Feel Free Travel | 2027, как в демо. |
| Удержание при возврате | Процент из настроек организации (по умолчанию 10%), менеджер может изменить сумму вручную. |
| Источники авиабилетов и отелей | Только mock-провайдеры до списка от эксперта. |
| Тексты договоров и расписок | Черновые тексты в сидах, помечены «согласовать с юристом». |
| Реальные интеграции (WhatsApp, Tourvisor, NCALayer, Telegram) | Интерфейсы + mock; реальные адаптеры — каркас, включаются ключами в `.env`. |
| Импорт варианта со скриншота (ИИ) | Только парсинг текста/ссылки; скриншоты — после выбора ИИ-провайдера. |
| Казахский язык интерфейса | Только ключи i18n, перевод позже. |

## Фаза 2 — данные

| Решение | Почему |
|---|---|
| Бизнес-логика в `shared/domain/*`, а не `server/domain` | Те же расчёты нужны в интерфейсе (живой пересчёт конструктора туров, подсказки регламента). Модули чистые, без БД, покрыты тестами. |
| Демо-даты сдвигаются к дню запуска сида | В прототипе «сегодня» = 22.10.2026. Сид сдвигает все рабочие даты (заявки, задачи, выезды, сообщения) так, чтобы этот день стал днём запуска — иначе демо сразу «устаревает». Туры конструктора (2027) не сдвигаются. |
| Сид очищает всю базу | Демо-стенд. В продакшене сид не запускать. |
| В демо включены все модули, кроме миграции | Чтобы были видны пакетные заявки из прототипа. Для новых агентств — значения по умолчанию из `docs/01_PRODUCT.md`. |
| Добавлен пользователь колл-центра `callcenter@demo.travel` | Для проверки роли «Колл-центр». Дана — менеджер (в прототипе «визовый менеджер»), в отпуске. |
| Требование «Туристы» выполнено, когда туристов не меньше, чем человек в заявке, **и у всех внесён паспорт** | Так звучит требование в регламенте («Туристы с паспортными данными»). |
| Автопереход может пройти несколько этапов подряд | Если данные следующего этапа уже заполнены — заявка идёт дальше, но не дальше последнего этапа (его завершает менеджер). |
| Пароли — argon2 (`@node-rs/argon2`) | Готовые бинарники, без компиляции в Docker. |
| Номер брони у оператора и другие «свободные» поля регламента хранятся в `Deal.reqValues` | В черновике схемы для них не было места. |

## Фаза 6 — документы и подписание

| Решение | Почему |
|---|---|
| Два вида шаблонов: загруженный DOCX и текстовый | DOCX заполняется docxtemplater (переменные в одинарных скобках `{Имя}`) и конвертируется в PDF через Gotenberg/LibreOffice. Текстовые шаблоны (так заданы демо-договоры и расписки) превращаются в HTML и в PDF через Gotenberg/Chromium. PDF из пользовательского файла как шаблон не принимается — переменные в PDF не подставить; его текст можно вставить. |
| Если Gotenberg недоступен — документ всё равно отправляется | Подписание идёт по тексту; PDF собирается при скачивании или заменяется простым PDF-заглушкой. |
| Подпись: mock по умолчанию, каркас NCALayer в браузере | Страница подписания сама находит запущенный NCALayer (`wss://127.0.0.1:13579`) и подписывает CMS через модуль `kz.gov.pki.knca.basics`. Проверка сертификата НУЦ РК на сервере (`SIGNING_PROVIDER=real`) требует отдельного сервиса проверки — подключается после MVP. eGov Mobile: QR показывается, в демо подпись подтверждается кнопкой. |
| Пароль ключа ЭЦП никогда не отправляется на сервер | В демо-окне NCALayer поле пароля только для вида. |
| Расписки «одной ссылкой» | Несколько расписок, отправленных вместе, получают общий `bundle`; клиент подписывает их на одной странице одним действием. |
| Новый договор по тому же шаблону аннулирует неподписанный старый | Чтобы в заявке не копились черновики. Подписанный аннулировать нельзя. |
| Рекомендуемый шаблон | Сначала договоры этой воронки, с учётом визы у выезда (визовый / по Казахстану), затем по числу недостающих полей. |

## Фазы 7–8 — групповые и пакетные туры

| Решение | Почему |
|---|---|
| Публикация тура добавляет ссылку-метку `T-<slug>` в правила распределения | Кнопка «Забронировать в WhatsApp» на публичной странице отправляет сообщение с меткой — заявка сразу попадает в групповую воронку на нужный выезд (правило 1). |
| Минимум выезда при публикации = точка безубыточности | По формулам конструктора; можно изменить в карточке выезда. |
| Выезд считается визовым, если среди стран тура есть страны вне безвизового списка (Казахстан, Турция, ОАЭ, Грузия, Узбекистан, Кыргызстан) | Влияет на шаги участника и блок «Виза» в заявке. Можно уточнить вручную. |
| Медиа туров лежат в S3 под `public/` и раздаются через `/api/public/media/…` | Публичная страница и превью в мессенджерах; документы заявок остаются закрытыми. |
| Поиск туров — mock с появлением результатов по операторам; Tourvisor — каркас запроса | Без токена работает mock. Разбор ответа Tourvisor подключается вместе с реальным токеном (нужен доступ к API для агентств). |
| Импорт варианта: текст — локальный парсер; скриншот/PDF — Claude (официальный SDK, модель `claude-opus-5-5`, структурированный ответ по схеме) | Включается ключом `ANTHROPIC_API_KEY`. Включён серверный fallback при отказе модели (`fallbacks: "default"`). Без ключа менеджер заполняет форму сам. |
| Автоматическое заполнение регламента пакетной воронки | Отправка подборки отмечает «Подборка отправлена», «Клиент выбрал» заполняет «Какой вариант выбрал клиент», номер брони — «Номер брони у туроператора», полная оплата оператору — «Оплата туроператору проведена». |
| Авиабилеты и отели — демо-источники, мониторинг цен каждый час через pg-boss | Список реальных источников даст эксперт. |
| Особенность `vue-tsc`: строки с `https://` внутри атрибутов шаблона ломают проверку типов | Адреса вынесены в скрипт. Не писать URL прямо в атрибутах `placeholder`/`:to` в шаблонах. |
